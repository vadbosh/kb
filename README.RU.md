# kb

**Хранилище знаний в обычном Markdown, где индекс не может устареть, а каждый
факт типизирован по тому, как он перестаёт быть верным.**

Годится для чего угодно, что иначе копится грудой `.md` — миграция, инцидент,
исследование, ремонт квартиры, судебное дело. К коду отношения не имеет.

[English version](README.md) · Полный мануал: [Русский](docs/kb.ru.md) · [English](docs/kb.en.md)

**Просто начать?** → [Установка](#установка), затем [Использование](#использование). Три шага.

## Идея

Почти каждый рано или поздно пишет себе вики по своей работе: один файл со
списком остальных, вокруг — файлы по темам. Работает недели три.

Потом файлы добавляются, переименовываются, делятся. Список правится руками —
пока не перестаёт. В разделе «текущее состояние» стоит дата, которую никто не
обновил. Ссылки ведут на переехавшие файлы. Типичная археология — стопка
`00-overview.md.bak.*` рядом с рабочим каталогом, по одной на каждую попытку
удержать всё это в честном виде.

kb убирает две причины из трёх механически, а третью делает видимой.

### 1. Индекс генерируется, а не поддерживается

В каждой заметке три строки front matter:

```yaml
---
title: что читатель здесь найдёт
kind: reference
updated: 2026-09-01
---
```

В указателе есть **управляемый блок**. Всё между маркерами пересобирается из этих
строк, всё вне них — твоё и не трогается никогда.

```markdown
## С чего начинать чтение

<!-- kb:begin -->
Актуальный срез: `21-state-2026-08-07.md` (2026-08-07).

| что нужно | файл | тип | обновлён |
|---|---|---|---|
| как устроен конвейер | `02-pipeline.md` | reference | 2026-08-05 |
| грабли и команды проверки | `23-traps.md` | recipe | 2026-08-07 |
<!-- kb:end -->
```

Эту таблицу ты не пишешь. Она не может разойтись с файлами, потому что выведена
из них.

### 2. Знание типизировано по способу устаревания

Именно этого у обычной вики нет. Заметка о том, **как что-то устроено**, и
заметка о том, **что происходило во вторник**, стареют совершенно по-разному, и
смешивание их — причина, по которой вики перестают вызывать доверие.

| kind | что хранит | как стареет |
|---|---|---|
| `state` | срез на дату | **вытесняется** более поздним |
| `plan` | что запланировано, в каком порядке | вытесняется по выполнении |
| `decision` | решение и **почему**; отвергнутые варианты | **не устаревает** — исторический факт |
| `reference` | как что-то устроено | правится на месте |
| `recipe` | грабли и готовые команды проверки | правится на месте |

Что инструмент получает из этого бесплатно:

- **Актуальный срез вычисляется**, а не объявляется — это `state` с наибольшей
  датой в имени файла. Прежние помечаются, но не удаляются: каждый по-прежнему
  правдиво описывает своё число.
- **`decision` никогда не переписывается.** Отмена решения — это новое решение,
  которое вытесняет прежнее. Рассуждение, приведшее к старому выбору, остаётся
  читаемым, а через полгода обычно именно оно и нужно.

### 3. Гниение сообщается по двум разным каналам

```
kb check     механика: индекс против файлов, битые ссылки, front matter, размер
kb verify    подозрения: пропавшие пути, заметки, куда давно не заглядывали
```

Намеренно **не слиты в одно**. `check` бинарный — выход 3 значит «иди и почини».
`verify` вероятностный — выход 3 значит «иди и посмотри». Слить их — утопить
точный сигнал в догадках.

Ни один не берётся судить, верно ли ещё утверждение о внешнем мире. В рецепте
может лежать команда, которая это докажет; запускать её по расписанию против
прода — не дело инструмента для заметок.

---

## Чего он намеренно не делает

- **Не дробит длинные файлы сам.** Размер сообщается, но не навязывается.
  Длинный связный `reference` — хороший файл; где резать, это вопрос смысла.
  `kb outline` печатает карту разделов, чтобы решение стоило прочитать десяток
  строк, а не полторы тысячи.
- **Ни базы, ни сервера, ни привязки.** Заметки — обычный Markdown в твоём
  репозитории. Удали инструмент, они останутся читаемыми; перестанет обновляться
  только таблица.
- **Никаких мнений о твоей прозе.** Генерируется исключительно управляемый блок.

## Два слоя

| Слой | За что отвечает | Где живёт |
|---|---|---|
| CLI `kb` | всё **механическое** — номера, таблица, детект дрейфа, какой срез актуален | `<skill-dir>/scripts/kb` |
| Skill `kb` | всё, где нужно **суждение** — новый файл или существующий, какой `kind`, когда в файле выросло два вопроса | каталог скиллов ассистента |

Это разделение и есть замысел. Ни одна сторона не делает работу другой: CLI
никогда не догадывается о смысле заметки, ассистент никогда не правит таблицу
руками.

У скилла две половины, каждая подгружается только когда нужна:

```
kb/SKILL.md               роутинг + правила, общие для обеих половин
kb/references/save.md     запись: дописать или новый файл, какой kind, заголовки
kb/references/restore.md  чтение: сориентироваться, читать выборочно, брифинг
kb/scripts/kb             CLI — одна копия, без зависимости от PATH
```

Написано под ассистентов, читающих `SKILL.md` — Claude Code, Opencode, Codex.
CLI работает и сам по себе, если удобнее гонять руками.

## Установка

Нужен **Python 3.10+** и больше ничего. Ни pip, ни пакетов, ни sudo.

```bash
git clone https://github.com/vadbosh/kb && cd kb

./install.sh              # Linux / macOS
./install.sh --dry-run    # напечатать что будет, ничего не менять
./install.sh --with-path  # плюс положить kb в PATH, для запуска руками
```

```powershell
.\install.ps1             # Windows
.\install.ps1 -DryRun
.\install.ps1 -WithPath

# если execution policy блокирует файл:
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

Оба проверяют Python прежде, чем что-то тронуть, и останавливаются с цветным
внятным сообщением, если его нет или он не в PATH — на Windows это частый исход,
когда при установке не отметили «Add python.exe to PATH».

Всё складывается в один каталог на ассистента:

```
<skills-dir>/kb/SKILL.md
<skills-dir>/kb/references/*.md
<skills-dir>/kb/scripts/kb        + лончер kb.cmd на Windows
```

Ничто не зависит от `PATH` или от существования `~/.local/bin` — на Windows такого
каталога просто нет, и по той же причине Windows-установщик пишет `.cmd`-лончер
(shebang там не работает).

Пишется только в те каталоги ассистентов, которые уже существуют; перебить
детект — `--skills-dir <путь>` / `-SkillsDir <путь>`. Установка руками сводится к
`cp -r skills/kb <skills-dir>/` — скилл самодостаточен.

Повторный запуск установщика для неизменённых файлов — настоящий no-op, а всё, что
заменяет, бэкапит как `<файл>.bak.<timestamp>`.

## Использование

Что нужно сделать, по порядку:

1. **Установить** — `./install.sh` (Linux/macOS) или `.\install.ps1` (Windows).
   Раздел [Установка](#установка).
2. **Зайти в каталог проекта** и запустить там ассистента.
3. **Написать `/kb save`.** Именно этот шаг создаёт `kb/` и пишет первую заметку.
   До него никакого `kb/` в проекте нет — запуск ассистента его не создаёт, и это
   нормально.

Дальше вся работа — две команды:

```
/kb restore    первым делом, когда садишься за работу — загрузит заметки,
               скажет что изменилось
/kb save       когда появилось что сохранить
```

Всё. `kb` в терминале ты не запускаешь — это делает ассистент.

Слова `kbrestore` и `kbsave` в обычном сообщении работают точно так же — что
проще запомнить, тем и пользуйся.

<details>
<summary>Что за этими двумя стоит</summary>

| Команда | Под капотом |
|---|---|
| `/kb restore` | `kb status` + `kb check` + `kb verify`, затем указатель и актуальный срез, затем только нужные задаче файлы |
| `/kb save` | `kb status` → решает дописать-или-новый → `kb add` → пишет тело → `kb sync` → `kb check` |

</details>

### Если заметки уже есть

Каталог с рукописным указателем и пронумерованными файлами переносится так:

```bash
kb adopt              # превью: что переедет, какие заголовки подберёт
kb adopt --apply
```

Заметки переезжают в `kb/`, добавляется front matter, вставляются маркеры,
собирается таблица. Заголовки **берутся из твоей существующей таблицы**, а не
выдумываются из `# H1`: формулировка, написанная человеком для читателя,
отвечает на «что мне нужно», а название документа — нет, и потерять её значило бы
свести затею на нет. Каждый тронутый файл сначала бэкапится.

## Команды

| Команда | Что делает |
|---|---|
| `kb status` | где kb, сколько файлов, какой срез актуален, самые крупные |
| `kb check` | механические расхождения; выход 3 = чини |
| `kb verify` | подозрения: пропавшие пути, залежавшиеся заметки |
| `kb sync` | пересобрать таблицу из front matter |
| `kb add <slug> --kind <k> --title "…"` | следующая нумерованная заметка + front matter + пересборка |
| `kb outline [файл]` | карта разделов с весами — где швы для дробления |
| `kb list [--scan DIR] [--prune]` | все kb, известные на этой машине |
| `kb adopt [--apply] [--in-place]` | миграция рукописного каталога заметок |
| `--dir X` | работать в X вместо `./kb` |

## Настройки

| Переменная | По умолчанию | Что определяет |
|---|---|---|
| `KB_LANG` | `ru` | язык текста, который пишется **внутрь** заметок — шапка таблицы, строка «Актуальный срез», скелет указателя. Диагностика всегда английская. |
| `KB_REGISTRY` | `$HOME/.local/state/kb/registry.txt` | где лежит список известных каталогов kb |
| `KB_DOC_DIR` | `$HOME/.kb-docs` | куда ставить мануал |
| `KB_BIN_DIR` | `$HOME/.local/bin` · `%LOCALAPPDATA%\kb\bin` | куда ставить необязательную копию в PATH |

Команда, пишущая заметки по-английски, один раз ставит `KB_LANG=en`. Существующие
заметки это не затрагивает — настройка действует только на текст, порождённый
после. Новый язык — один ключ в словаре `STRINGS` внутри CLI.

Ни один путь нигде не прибит к конкретной машине.

## Заметки по устройству

Что стоит знать, прежде чем дописывать:

- **Дыры в нумерации не переиспользуются.** Номер, на который когда-то ссылались,
  может до сих пор упоминаться в сообщении коммита или в другой заметке.
- **Порядок строк — по номеру**, поэтому правка одного файла не перетасовывает
  таблицу и диффы остаются мелкими.
- **`verify` проверяет только пути в бэктиках, у которых существует корень.**
  Замер на живом kb из 19 файлов: без этих двух условий получается 271 флаг, из
  которых настоящих около 2 — URL-пути, версии API, обрубки длинных путей. С
  условиями: 6 флагов, 2 настоящих. Отчёт с первым соотношением научит себя
  игнорировать за пару дней. Цена — путь внутри код-блока не проверяется.
- **Пороги размера 400 и 1200 строк.** Знакомое правило «не больше 200 строк»
  относится к файлам инструкций, которые грузятся в контекст каждый ход. Эти
  читаются по требованию, по одному, так что оно не переносится.
- **Front matter парсится без зависимости от YAML** — плоские пары `key: value`
  между `---`, разделение по первому двоеточию, чтобы заголовки могли его
  содержать.

## Удаление

```bash
rm -rf <skills-dir>/kb
rm -f  ~/.local/bin/kb        # только если ставили с --with-path
rm -rf ~/.local/state/kb      # реестр
rm -rf ~/.kb-docs
```

Заметки не тронуты — они никогда не были внутри инструмента.
