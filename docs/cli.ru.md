# kb — командная строка сама по себе

**kb — обычная программа для терминала. Ни ассистента, ни IDE, ни плагина к
редактору, ни файла настроек, ни фоновой службы, ни сети.** В остальной
документации он показан через `/kb save` из ассистента, потому что так удобнее.
Эта страница — про другой способ: вы, терминал и каталог.

Работает **в любом каталоге, в том числе в пустом**. Готовить заранее нечего:
каталог с заметками появляется на первой же записи.

```bash
mkdir /tmp/incident && cd /tmp/incident
kb add timeline --kind state --title "что произошло, по минутам"
```

Это вся подготовка. Ни проекта, ни репозитория, ни конфигурации не потребовалось.

Нужен **Python 3.10+** и больше ничего.

## Откуда берётся содержимое и что становится источником индекса

Первый вопрос без ассистента: а что, собственно, kb туда запишет?

**Ровно то, что вы набрали в командной строке, и ни байтом больше.** `kb add`
создаёт файл из семи строк: три поля front matter и заголовок `# `, повторяющий
`--title`. Тело пустое:

```console
$ kb add pipeline --kind reference --title "как устроен конвейер логов"
$ cat kb/01-pipeline.md
---
title: как устроен конвейер логов
kind: reference
updated: 2026-08-08
---

# как устроен конвейер логов
```

`title` берётся из `--title`, `kind` из `--kind`, `updated` — сегодняшняя дата.
Больше kb не придумывает ничего: ни текста, ни выводов, ни тегов. Содержимое
пишет человек в редакторе — или ассистент, если он есть. Инструмент ведёт учёт,
а не сочиняет.

**Источником индекса служит front matter файлов `NN-*.md` — эти три поля, и
только они.** Тело заметки не читается никогда, сколько бы текста в нём ни было:

```console
$ echo 'много текста в теле' >> kb/01-pipeline.md
$ kb sync
index already current (4 files)          ← таблица не шелохнулась

$ sed -i 's/^title: .*/title: другой заголовок/' kb/01-pipeline.md
$ kb sync
index rewritten: 4 files                 ← а вот теперь перестроилась
```

Отсюда и обещание, что указатель не может разойтись с файлами: он из них и
получен, причём из той их части, которая специально для этого и заведена.

**А если front matter нет вовсе** — например, файл написан руками до знакомства
с kb, — заметка из указателя не выпадает. kb достраивает недостающее по
догадке: заголовок берёт из первого `# `, тип считает `reference`. И честно
помечает это как догадку:

```console
$ kb check
2 problem(s):
  - index table is stale — run `kb sync`
  - 05-handmade.md: no front matter (kind/title guessed)
```

Догадка работает, но живёт до первой правки: пропишите поля явно, и файл
перестанет быть особым случаем. `kb adopt` делает это по всему каталогу разом —
а перед тем переименовывает всё, что не в схеме `NN-slug.md`, потому что
рукописный каталог в ней почти никогда не бывает. Сначала показывает, потом
пишет; копию каждого файла проверяет и удаляет, когда запись подтверждена.

## Где взять сам файл

CLI лежит внутри каталога скилла, поэтому работает независимо от того, установлено
ли что-то ещё:

```
<skills-dir>/kb/scripts/kb        Linux / macOS
<skills-dir>\kb\scripts\kb.cmd    Windows
```

Для повседневной работы из терминала стоит один раз положить его в `PATH`:

```bash
./install.sh --with-path          # при установке
# либо руками:
ln -s ~/.claude/skills/kb/scripts/kb ~/.local/bin/kb
```

Дальше везде написано просто `kb`; полный путь работает точно так же.

## От пустого каталога до готового хранилища

Все блоки ниже — настоящий вывод, а не иллюстрация.

**В пустом каталоге заметок нет, и kb об этом говорит, а не выдумывает их:**

```console
$ ls -a
$ kb status
kb: no 00-overview.md in ./kb or . — run `kb init` first, or pass --dir
$ echo $?
1
```

**Первая заметка создаёт всё, что ей нужно:**

```console
$ kb add pipeline --kind reference --title "как устроен конвейер логов"
created /tmp/clidemo/kb/00-overview.md
created /tmp/clidemo/kb/01-pipeline.md
index rewritten: 1 files
```

Два файла: указатель и заметка. `kb init` умеет создать только указатель, но он
не обязателен — `kb add` делает это сам, когда каталог пуст.

**Заметка — обычный Markdown с тремя полями front matter:**

```console
$ cat kb/01-pipeline.md
---
title: как устроен конвейер логов
kind: reference
updated: 2026-08-08
---

# как устроен конвейер логов
```

Тело пишется любым редактором. kb его не трогает.

```bash
$EDITOR kb/01-pipeline.md
```

**Остальные типы добавляются по ходу работы:**

```console
$ kb add traps --kind recipe --title "известные проблемы и команды проверки"
created /tmp/clidemo/kb/02-traps.md
index rewritten: 2 files

$ kb add state --kind state --title "что сделано, что открыто"
created /tmp/clidemo/kb/03-state-2026-08-08.md
index rewritten: 3 files
```

`state` получает сегодняшнюю дату в имя автоматически — по ней kb потом и
вычисляет, какой срез актуален.

**Посмотреть, что получилось:**

```console
$ kb status
kb root: /tmp/clidemo/kb   files: 3
current state: 03-state-2026-08-08.md (2026-08-08)
  state      1
  reference  1
  recipe     1
```

## Единственное правило при правке руками

Таблица указателя **генерируется**. Правьте front matter, затем запускайте
`kb sync` — но не саму таблицу.

```console
$ sed -i 's/^title: .*/title: как логи доезжают от пода до коллектора/' kb/01-pipeline.md
$ kb check
1 problem(s):
  - index table is stale — run `kb sync`

secrets: none found — checked with built-in patterns + trufflehog
$ echo $?
3

$ kb sync
index rewritten: 3 files

$ kb check
clean: 3 files, index current
```

Промежуток между правкой файла и `kb sync` — единственный момент, когда указатель
может врать, и `check` его закрывает. Всё, что вне маркеров `kb:begin` и
`kb:end`, принадлежит вам, kb туда не пишет.

Пересобранная таблица:

```markdown
<!-- kb:begin -->
Актуальный срез: `03-state-2026-08-08.md` (2026-08-08).

| что нужно                                   | файл                     | тип       | обновлён   |
|---------------------------------------------|--------------------------|-----------|------------|
| как логи доезжают от пода до коллектора     | `01-pipeline.md`         | reference | 2026-08-08 |
| известные проблемы и команды проверки       | `02-traps.md`            | recipe    | 2026-08-08 |
| что сделано, что открыто                    | `03-state-2026-08-08.md` | state     | 2026-08-08 |
<!-- kb:end -->
```

## Какие каталоги трогала сессия

`kb streams` отвечает на вопрос, которого не задаёт ни одна другая команда: где
за эту сессию на самом деле шла работа. Она читает стенограмму самой оболочки —
Claude Code и Codex держат файлы JSONL, Opencode базу sqlite — и достаёт оттуда
**каталоги**, а не текст реплик.

```console
$ kb streams
  read: claude ×1

   21  ~/src/api
   13  ~/src/deploy
   11  /srv/gateway

  mentioning no path (93) — work with no directory does not appear above at all:
    • посмотри journal, может там есть ошибки mysql
```

Пути вместо реплик — намеренно: спрашивается, какие каталоги, и такой ответ
обходится примерно вдесятеро дешевле.

```bash
kb streams                  # текущая сессия
kb streams --sessions 3     # когда работа шла не в одной
kb streams --top 20         # больше каталогов
```

Зачем это нужно: после долгой сессии, а особенно после сжатия переписки,
припоминание выдаёт то, что свежее, и выглядит полным в любом случае. Эта команда
не припоминает, а читает.

Двух вещей она не умеет. Работа **без каталога** — веб-консоль, правило в почте,
хост, до которого добирались по ssh, — не оставляет чего доставать; хвост из
реплик без путей это подсказка, а не второй список. А если оболочка стенограмму
не ведёт, команда так и скажет, и список остаётся за вами.

## Работа из другого места

`--dir` указывает на **существующие** заметки из любого текущего каталога —
именно это позволяет звать kb из скрипта или из cron:

```console
$ cd /
$ kb --dir /tmp/clidemo/kb status
kb root: /tmp/clidemo/kb   files: 3
current state: 03-state-2026-08-08.md (2026-08-08)
```

Каждый каталог, который kb на этой машине видел, он запоминает, так что держать
пути в голове не нужно:

```console
$ kb list
  /srv/logging/kb                          3 files, snapshot 2026-08-05
  /srv/gateway/kb                          19 files, snapshot 2026-08-07, ⚠ 1 heavy
  /tmp/clidemo/kb                          3 files, snapshot 2026-08-08
```

```bash
kb list --scan ~/projects   # подобрать каталоги, заведённые до реестра
kb list --prune             # забыть записи, у которых каталог пропал
```

**Новое хранилище создаётся только внутри текущего каталога.** `--dir` дотянется
до существующего где угодно, но развернуть новое в стороне не даст; `$HOME`,
любой каталог из `PATH` и системные корни отвергаются сразу. Нужны заметки в
другом месте — это одна команда `cd`, и она заявляет намерение, чего молчаливый
путь в аргументе не делает.

## Справочник команд

| Команда | Что делает |
|---|---|
| `kb add <slug> --kind <k> --title "..."` | новая заметка, front matter, пересборка указателя; создаст `kb/`, если его нет |
| `kb status` | где хранилище, сколько файлов, какой срез актуален, самые крупные файлы |
| `kb check` | механические расхождения и учётные данные |
| `kb verify` | подозрения: пропавшие пути, заметки, куда давно не заглядывали |
| `kb sync` | пересобрать таблицу из front matter |
| `kb outline [файл]` | карта разделов с весами; без аргумента — все файлы длиннее 400 строк |
| `kb list [--scan DIR] [--prune]` | все хранилища, известные на этой машине |
| `kb streams [--sessions N]` | какие каталоги трогала сессия — читается из стенограммы |
| `kb init [--title ...]` | только скелет указателя |
| `kb adopt [--apply] [--in-place]` | принять рукописные заметки: нумерует ненумерованные `.md`, дописывает front matter, собирает указатель |
| `kb hook` | поставить git pre-commit, отклоняющий коммит с учётными данными |

Флаги: `--dir <путь>` к любой команде, `--supersedes <файл>` к `add`,
`--no-sync` к `add`, чтобы не пересобирать указатель.

### Коды возврата

| Код | Что значит | Что делать в скрипте |
|---|---|---|
| 0 | чисто | продолжать |
| 1 | ошибка вызова либо по указанному пути хранилища нет | исправить вызов |
| 2 | неверные аргументы | исправить вызов |
| 3 | найдено расхождение (`check`) или что-то подозрительное (`verify`) | посмотреть и решить |
| 4 | **в заметке найдены учётные данные** | остановиться, не коммитить |

Код 3 у `check` и у `verify` намеренно означает разное. `check` механический:
3 — это дефект, который надо устранить. `verify` эвристический: 3 — повод
посмотреть глазами, и вполне может оказаться, что всё в порядке.

```bash
kb check || case $? in
  3) echo "расхождение — нужен kb sync или разбор отчёта" ;;
  4) echo "в заметках учётные данные, коммит отменён"; exit 1 ;;
esac
```

## Переменные окружения

| Переменная | На что влияет |
|---|---|
| `KB_LANG` | язык текста, который kb пишет **внутрь** заметок: `ru` по умолчанию либо `en`. Диагностика остаётся английской. |
| `KB_REGISTRY` | где лежит список известных хранилищ; по умолчанию `~/.local/state/kb/registry.txt` |

```console
$ KB_LANG=en kb add pipeline --kind reference --title "how the log pipeline works"
$ sed -n '/kb:begin/,/kb:end/p' kb/00-overview.md
<!-- kb:begin — generated by `kb sync`, do not edit by hand -->

| what you need | file | kind | updated |
|---|---|---|---|
| how the log pipeline works | `01-pipeline.md` | reference | 2026-08-08 |
```

Задавать удобно на проект — в профиле оболочки или в файле direnv. На уже
написанный текст переключение не влияет, только на новый.

## Где CLI действительно нужен

Честно говоря, случая два: **машина делает это без вас** и **ассистента рядом
нет**. Всё остальное удобнее через `/kb`.

### Обход всех хранилищ по расписанию

Заметки про инфраструктуру набиты путями — к каталогам конфигов, к скриптам, к
точкам монтирования. Протухают они молча: кто-то переименовал каталог, а заметка
продолжает указывать на старый. Открывать ради этого ассистента никто не станет.
Cron станет:

```cron
0 9 * * 1  kb list | awk '/^ *\// {print $1}' | while read -r d; do kb --dir "$d" verify; done
```

Обратите внимание на `^ *`: `kb list` печатает с отступом, и якорь без пробелов
не совпадёт ни с чем. Чтобы письмо приходило только когда действительно есть о
чём:

```bash
kb list | awk '/^ *\// {print $1}' | while read -r d; do
  out=$(kb --dir "$d" verify 2>&1) || { echo "── $d"; echo "$out" | grep '✗'; }
done
```

На двух живых хранилищах это напечатало (пути здесь и ниже заменены на
условные — вывод настоящий, каталоги чужие):

```
── /srv/gateway/kb
    ✗ /etc/nginx/custom-conf-parts/
    ✗ /etc/nginx/custom-lua-scripts/
```

Четыре пути, на которые ссылается заметка и которых на этой машине больше нет.
Возможно, они живут внутри контейнера — `verify` сообщает о подозрении, а не о
факте, — но именно этот список стоит просматривать глазами раз в неделю.

### Отклонить коммит с учётными данными

`kb check` даёт код 4, когда находит их, и 4 — единственный код, который стоит
трактовать как жёсткий стоп. Внутри git-репозитория:

```bash
kb hook
```

Чужой pre-commit он не перезапишет — напечатает строку, которую нужно дописать
руками. В CI, когда заметки лежат в репозитории:

```yaml
kb-check:
  script:
    - kb --dir docs/kb check || [ $? -ne 4 ]
```

Так код 3 (расхождение индекса) проходит, а находка учётных данных валит job.
Разверните условие, если хотите валить и на устаревшем индексе.

### Машина, где ассистента нет

kb — один файл без зависимостей, так что вся установка сводится к `scp`.
Разбираясь в три ночи, почему база перестала отвечать, можно записать `recipe`
прямо там, где нашли, а не держать это в голове до утра.

### kb как цель записи для других программ

Заметку может создать любой скрипт. Про это обычно не думают:

```bash
kb add apply-$(date +%s) --kind state \
   --title "что изменил этот terraform apply" --dir /srv/infra/kb
```

Обёртка вокруг `terraform apply`, разбор инцидента, ночной отчёт — всё это может
складывать результат в то же хранилище, которое потом читает ассистент. kb
перестаёт быть блокнотом ассистента и становится форматом, в который умеет писать
остальная обвязка.

### Ориентировка, которая ничего не стоит

`kb status` отвечает за миллисекунды и говорит, какой срез актуален и какие файлы
самые тяжёлые. Иногда нужно ровно это, а заводить ради него сессию — избыточно.

### Коллеги, которые ИИ не пользуются вообще

Это Markdown плюс одна команда. Чтобы читать хранилище, устанавливать не нужно
ничего. Именно поэтому его можно отдать в команду, где не все работают одинаково.

### Чего в этом списке намеренно нет

Повседневной записи руками. Набирать `kb add --kind --title` каждый раз, когда
что-то выяснил, — работа, которую ассистент делает лучше, потому что интересное в
ней это суждение: дописать или завести новый файл, какой `kind` подходит, как
сформулировать заголовок для читателя, а не для себя. CLI за это не берётся —
см. последний раздел.

---

## Чего CLI за вас не сделает

Он не решает, **что** записать, дописать ли факт в существующий файл или завести
новый, какой `kind` подходит. Это суждение, и живёт оно в скилле — потому и
разумно водить kb через ассистента, когда он есть. Без ассистента эти решения
ваши, а рекомендации — в [мануале](kb.ru.md).

Тела заметок он тоже не пишет. `kb add` создаёт файл и front matter; то, что
ниже, пишет человек или ассистент, в редакторе.
